# ed25519-signer

Минимальный консольный подписыватель для MeshCore-совместимых Ed25519-ключей. Умеет:

- генерировать пару ключей (64-байтовый приватный, 32-байтовый публичный);
- сжимать текст словарём, добавлять timestamp и подписывать;
- выдавать один headerless-блоб;
- проверять блоб публичным ключом и распаковывать текст.

Единственная зависимость — `PyNaCl`. Планов, спецификаций и прочих документов в проекте нет.

## Установка

Нужен Python 3.10+.

```bash
python3 -m venv .venv
.venv/bin/pip install -r requirements.txt
```

## Быстрый старт

```bash
# 1. Ключи
./ed25519_signer.py keygen --out keys/repeater

# 2. Команда для подписи
printf 'set radio 869.618,62.5,8,5\n' > command.txt

# 3. Подпись в бинарный блоб
./ed25519_signer.py sign \
    --key keys/repeater.priv \
    --in command.txt \
    --format bin \
    --out packet.bin \
    --out-format bin

# 4. Проверка и распаковка
./ed25519_signer.py verify \
    --pub keys/repeater.pub \
    --in packet.bin \
    --format bin \
    --show-timestamp
```

`keygen` печатает оба ключа в hex и создаёт:

- `keys/repeater.priv` — 128 hex-символов, права `0600`;
- `keys/repeater.pub` — 64 hex-символа.

Приватный ключ совместим с MeshCore: это 64-байтовый expanded key (SHA-512 от seed с зажатыми первыми 32 байтами). Публичный ключ выводится из него и совпадает с результатом `lib/ed25519` из MeshCore. Подпись также совпадает байт-в-байт. Если публичный ключ начинается с `0x00` или `0xFF`, `keygen` сразу генерирует другой — такие ключи MeshCore не принимает.

## Команды

```text
ed25519_signer.py keygen [--out PREFIX] [--force]

ed25519_signer.py sign --key FILE [--in FILE] [--format bin|hex]
    [--out FILE] [--out-format bin|hex] [--timestamp N]
    [--max-size N] [--dictionary FILE]

ed25519_signer.py verify --pub FILE [--in FILE] [--format bin|hex]
    [--out FILE] [--max-size N] [--max-age N] [--show-timestamp]
    [--dictionary FILE]
```

- `--in -` — stdin, `--out -` — stdout (по умолчанию).
- У `sign` вход по умолчанию `bin` (сырые байты текста), выход по умолчанию `hex`.
- У `verify` вход по умолчанию `hex`, чтобы совпадать с выходом `sign` по умолчанию.
- `--format hex` означает, что входной файл содержит hex-текст, который надо декодировать.
- `--max-size 160` включён по умолчанию и у `sign`, и у `verify`; `0` отключает проверку.
- `--timestamp` — Unix UTC seconds; без него берётся текущее время.
- `--max-age` у `verify` — необязательная проверка свежести.
- `verify` выводит ровно те байты, которые были подписаны, без добавления newline.

Пример с hex-выводом:

```bash
./ed25519_signer.py sign \
    --key keys/repeater.priv --in command.txt \
    --out packet.hex --out-format hex

./ed25519_signer.py verify \
    --pub keys/repeater.pub --in packet.hex --format hex
```

## Формат блоба

```
blob = C || S
P    = timestamp_le32 || dict_id || cmdpack(text)
S    = Ed25519_sign(P)                  # 64 байта: R || s
C    = P XOR SHA512("MC1-mask" || R || counter)
```

- `timestamp` — 4 байта, little-endian, Unix UTC seconds.
- `dict_id` — 2 байта, первые два байта SHA-256 от списка токенов словаря.
- `S[:32]` — это `R`, он же seed для маски.
- `counter` — 0, 1, 2…, little-endian uint32; нужен, если payload длиннее 64 байт.
- Никакого magic/version/length в открытом виде нет. Последние 64 байта — подпись, остальное — маскированный payload.

Разбор на чипе:

1. Последние 64 байта — `S`.
2. Взять `R = S[:32]`, сгенерировать маску, снять её с `C` — получить `P`.
3. Проверить `S` над `P` сохранённым публичным ключом.
4. Прочитать timestamp и `dict_id`, проверить их.
5. Распаковать остаток `P` кодеком `cmdpack`.

Ограничение пакета: `160 − 64 = 96` байт на `P`; минус 4 байта timestamp и 2 байта `dict_id` — **90 байт под сжатый текст**. Если текст не влезает, `sign` завершится с ошибкой.

Маска — это обфускация, а не шифрование. Она убирает структуру и не даёт опознать формат по заголовку, но кто знает схему, может снять её. Для настоящей конфиденциальности нужен общий секрет и AEAD.

## Словарь

Словарь лежит рядом: `dictionary.txt`, один токен на строку. Сейчас в нём 254 токена: 156 слов из CLI-команд MeshCore и 98 одиночных ASCII-символов.

```
set
get
radio
blacklist
...
```

Правила:

- номер строки (с нуля) = код токена;
- порядок строк менять нельзя, иначе изменятся коды и `dict_id`;
- максимум 254 токена; дубликаты запрещены;
- пустые строки игнорируются;
- комментариев нет: строка, начинающаяся с `#`, — это токен;
- пробел, таб, перевод строки, CR и обратный слэш записываются как `\s`, `\t`, `\n`, `\r`, `\\`; произвольный байт — `\xNN`.

По умолчанию берётся `dictionary.txt` рядом со скриптом; файл в текущем каталоге — запасной вариант. Свой словарь передаётся явно:

```bash
./ed25519_signer.py sign ... --dictionary my_dictionary.txt
./ed25519_signer.py verify ... --dictionary my_dictionary.txt
```

Прошивка должна использовать тот же словарь в том же порядке. Иначе `dict_id` не совпадёт и `verify` откажется работать.

### Кодек cmdpack

- коды `0..N-1` — токены;
- `254` — literal-run: `[254][len][raw bytes]`;
- `255` — hex-run: `[255][len][packed nibbles]`, только lowercase hex;
- если сжатие не уменьшает текст, весь текст кодируется literal-run;
- декодер читает payload до конца.

## Безопасность

- Приватный ключ хранится в открытом виде; файл создаётся с правами `0600`, но сам ключ не зашифрован.
- Повтор одной и той же команды в одну и ту же секунду даёт одинаковый блоб — так задумано.
- Timestamp в секундах не заменяет anti-replay: если это важно, чип должен проверять окно свежести или вести счётчик.
- `dict_id` — это проверка версии словаря, а не криптографическая защита. Словарь считается доверенным: если его подменить, 2-байтовый ID можно подобрать. Прошивка должна использовать тот же словарь, что и хост.
- Ed25519 даёт 64-байтовую подпись. Более короткие публично проверяемые схемы (например, BLS) ломают совместимость с MeshCore и тяжелы для nRF.
